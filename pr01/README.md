# Практическая работа № 1 — Пользователи, группы и права доступа

Вариант B.

## Цель работы

Создать дополнительного пользователя и общую группу, настроить каталог с наследованием группы, проверить права доступа и закрепить различия между `su`, `sudo` и учётной записью `root`.

## Выполнение

В Ubuntu были выполнены следующие действия:

```bash
sudo adduser student2
sudo groupadd developers
sudo usermod -aG developers student2
sudo mkdir -p /srv/shared
sudo chown root:developers /srv/shared
sudo chmod 2775 /srv/shared
```

Число `2` в режиме `2775` включает бит `setgid`: новые файлы внутри `/srv/shared` наследуют группу `developers`.

От имени `student2` создан файл:

```bash
su - student2
echo "Created by student2" > /srv/shared/student2.txt
exit
```

Для проверки использовались команды `id`, `ls -ld`, `ls -l` и `test -w`.

## Настройка окружения

В `~/.bashrc` были добавлены настройки:

```bash
alias ll='ls -lah'
alias cshared='cd /srv/shared'
export LAB_VARIANT=B
export SHARED_DIR=/srv/shared
```

После запуска новой сессии Bash значения проверены командами `alias` и `echo`.

## Результаты

Создан student2, включён в группу developers.
Каталог /srv/shared принадлежит root:developers, права 2775.
Члены группы могут создавать файлы, остальные — просматривать каталог.
Setgid обеспечивает наследование группы developers.

student2 создал файл student2.txt.
zeus не смог удалить его: Permission denied.
Для удаления нужны права записи и выполнения на каталог.
У zeus нет права записи в /srv/shared.

su переключает пользователя и обычно запрашивает пароль
целевого пользователя. su - загружает его окружение входа.
sudo выполняет разрешённую команду от имени другого пользователя,
по умолчанию root, обычно запрашивая пароль вызывающего пользователя.

В Ubuntu пароль root по умолчанию заблокирован, поэтому прямой
вход по паролю недоступен. Администрирование выполняют через sudo,
что позволяет ограничивать доступ и журналировать действия.
Учётная запись root при этом существует.
