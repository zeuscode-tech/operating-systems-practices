# Практическая работа №13 — планирование дисковых запросов

## Цель

Реализовать FCFS, SSTF, SCAN, C-SCAN, LOOK и C-LOOK, сравнить перемещение головки и показать компромисс между скоростью и справедливостью.

## Уровень A

Контрольные данные: цилиндры `0..199`, начальная позиция `53`, очередь `98 183 37 122 14 124 65 67`, направление вверх.

| Алгоритм | Перемещение |
|---|---:|
| FCFS | 640 |
| SSTF | 236 |
| SCAN | 331 |
| C-SCAN | 382 |
| LOOK | 299 |
| C-LOOK | 322 |

`disk.py` печатает полный порядок обслуживания и сохраняет `disk_results.csv`.

## Уровень B

`analysis.py` проверяет 20 воспроизводимых очередей по 50 запросов и строит `disk_comparison.png`. `starvation.py` показывает, что SSTF способен откладывать дальний запрос, пока рядом появляются новые.

SSTF дал минимум на контрольной очереди, но это не означает, что он всегда лучший: SCAN/LOOK обеспечивают более предсказуемое ожидание, а циклические варианты выравнивают обслуживание направлений.

## Уровень C

`fio_benchmark.sh` сравнивает последовательное и случайное чтение временного файла. Тест не пишет на реальные разделы и удаляет файл после выполнения.

```bash
sudo apt install fio
./fio_benchmark.sh
```

Для SSD механическое перемещение головки отсутствует, поэтому классические алгоритмы важнее как модель планирования, чем как точное описание современного накопителя.

## Запуск

```bash
./run_all.sh
python3 analysis.py
```
