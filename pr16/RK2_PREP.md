# Подготовка к РК‑2

## Память

- **Страница** — фиксированный блок виртуальной памяти процесса; **кадр** — блок того же размера в RAM.
- `page = address // page_size`, `offset = address % page_size`.
- `physical = frame × page_size + offset`.
- **TLB** — аппаратный кэш переводов page→frame.
- `EAT = h(TLB + memory) + (1-h)(TLB + 2×memory)` для простой таблицы.
- Внешняя фрагментация — свободное место разбито между блоками; внутренняя — остаток внутри выделенного блока.
- Page fault возникает, когда нужной страницы нет в RAM. Minor не требует диска, major требует ввода‑вывода.

## Файловые системы и диск

- inode хранит метаданные и адреса блоков; каталог связывает имя с inode.
- hard link — ещё одно имя того же inode; symbolic link — отдельный файл с путём.
- SSTF выбирает ближайший запрос, SCAN движется как лифт, LOOK разворачивается на последнем запросе.
- SSD не имеет механической головки, поэтому классические расстояния цилиндров для него условны.

## Ввод-вывод и защита

- Буферизация уменьшает число системных вызовов.
- Page cache ускоряет повторное чтение; `O_DIRECT` обходит его и требует выравнивания.
- Защита отвечает «кто что может», безопасность — как противостоять угрозам.
- Контейнер использует namespaces и cgroups, но делит ядро с хостом; VM имеет гостевое ядро.

## Частые вопросы

1. Почему при наличии свободной памяти запрос может не пройти? Нет одного непрерывного блока нужного размера.
2. Почему Optimal нельзя использовать буквально? Он должен знать будущие обращения.
3. Почему обход матрицы по строкам быстрее? Последовательные адреса лучше используют cache line и TLB.
4. Чем deadlock отличается от starvation? При deadlock участники образуют цикл и не двигаются; при starvation система работает, но отдельная задача не получает ресурс.
5. Почему Docker не равен VM? Docker изолирует процессы, но не запускает отдельное ядро.
