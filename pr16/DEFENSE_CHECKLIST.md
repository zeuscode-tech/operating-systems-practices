# Чек-лист итоговой защиты

## Перед занятием

- [ ] `git status` показывает чистое дерево.
- [ ] `python3 check_all.py` заканчивается строкой об успешной проверке.
- [ ] Открывается корневой README и README каждой практики.
- [ ] Для работ с графиками сохранены PNG, для измерений — TXT/CSV.
- [ ] Команды с `sudo` не выполняются на основном компьютере без необходимости.

## Что показать по практикам

| ПР | Демонстрация | Главный вывод |
|---:|---|---|
| 1 | права, группа, setgid | доступ определяют UID/GID и mode bits |
| 2 | Bash, `strace` | системные вызовы — интерфейс программы с ядром |
| 3 | fork/exec/wait, `/proc` | процесс имеет PID и отдельное адресное пространство |
| 4 | потоки и процессы | потоки делят память; GIL влияет на CPU-bound Python |
| 5 | FCFS/SJF/SRTF/RR | алгоритм меняет ожидание и справедливость |
| 6 | mutex/semaphore/condition | критическая секция устраняет гонку |
| 7 | pipe/FIFO/socket/shared memory | IPC различается скоростью и синхронизацией |
| 8 | banker/wait graph | deadlock требует четырёх условий Коффмана |
| 9 | first/best/worst/buddy | свободная память может быть фрагментирована |
| 10 | page→frame, TLB | TLB уменьшает стоимость трансляции адреса |
| 11 | FIFO/LRU/Optimal/Clock | Optimal эталон; FIFO имеет аномалию Белади |
| 12 | inode/link/backup | имя файла и inode — не одно и то же |
| 13 | SSTF/SCAN/LOOK | минимум перемещения может ухудшить справедливость |
| 14 | мелкие/блочные write | число переходов в ядро сильно влияет на скорость |
| 15 | namespaces/cgroups | контейнер — изолированный процесс на ядре хоста |
